1. Purpose and scope
This procedure validates one exoskeleton leg in a controlled bench setup before any human use.
The goal is to verify power, CAN communication, encoder feedback, joint zero references, angle limits, current consumption, forces, pressure sensors, and safe stop behavior.

Scope
 - One leg only
 - Hip, knee, and ankle tested separately before combined motion
 - First tests without load
 - Later tests on the mannequin
 - No human testing in this phase

Main risks
 - Unexpected motor movement
 - Wrong motor direction
 - Wrong joint zero reference
 - Excess current or voltage drop
 - Mechanical collision at joint limits
 - CAN communication loss
 - Motor or driver overheating

2. Required equipment
Control and actuator hardware
 - ESP32-S3 or ESP32-S3 Super Mini controller
 - SN65HVD230 3.3 V CAN transceiver
 - Cubemars AK80-64 KV80 motor for hip
 - Cubemars AK45-36 KV80 motors for knee and ankle
 - CAN wiring, motor power wiring, USB programming cable
 - PC with PlatformIO, serial monitor, and CubeMars/CAN tools if needed

Power and safety equipment
 - Adjustable DC power supply with current limit
 - Final battery or final DC source only after bench validation
 - Inline fuse or DC breaker
 - Emergency stop switch
 - Main power switch
 - Rigid fixture, bench vise, or mechanical support
 - Protective glasses and fire-safe test surface

Measurement equipment
 - Digital multimeter for voltage, continuity, and resistance checks
 - Clamp meter or inline current meter for supply current
 - Oscilloscope for CANH/CANL electrical signal inspection
 - CAN USB analyzer for independent CAN traffic monitoring
 - Logic analyzer only if needed to debug ESP32 TX/RX digital signals
 - IR thermometer or thermal camera for motor and driver temperature
 - Digital angle gauge or inclinometer for joint angle verification
 - Mechanical goniometer/protractor as a backup manual angle check
 - Spring scale or force gauge for simple force measurements
 - Weights for repeatable load tests
 - Calipers or ruler for link length and lever arm checks

Sensor equipment
 - FSR402 pressure sensors
 - Known resistors for voltage divider tests
 - Breadboard or small test PCB
 - Optional ESP32-S3 Super Mini foot sensor node

3. Pre-test inspection
Mechanical checks
 - Verify all screws, mounts, couplers, and brackets are tight
 - Move each joint by hand and confirm there is no binding
 - Confirm cables cannot enter a moving joint
 - Confirm cables are not stretched at the expected angle limits
 - Mark the mechanical neutral position and visible joint limits
 - Add mechanical end stops if available

Electrical checks with power off
 - Verify supply polarity
 - Verify there is no short between supply positive and ground
 - Verify ESP32 ground, CAN transceiver ground, and motor ground reference are connected as required
 - Verify SN65HVD230 is powered from 3.3 V
 - Verify CANH and CANL are not swapped
 - Verify CAN termination is present only at the bus ends
 - Verify each motor has a unique CAN ID

Firmware checks
 - Confirm board profile and CAN pins
 - Confirm motor IDs and joint mapping
 - Confirm direction signs for hip, knee, and ankle
 - Confirm initial angle limits are conservative
 - Confirm current, torque, speed, and temperature limits are configured
 - Confirm emergency stop and fault reset behavior

4. Initial power and CAN tests
Power-on without motor motion
 - Set the DC power supply current limit low
 - Power the controller first, without enabling motion
 - Measure 3.3 V and 5 V rails if present
 - Measure motor bus voltage
 - Confirm there is no unexpected heating or reset

CAN physical layer
 - Check idle CANH/CANL levels with oscilloscope if available
 - Send a simple status request or enable command
 - Confirm feedback frames are received from each motor
 - Use a CAN USB analyzer when possible to independently confirm traffic
 - Stop if CAN errors, missing feedback, or unstable communication appear

5. Encoder, homing, and zero reference procedure
Important distinction
 - The Cubemars motors include a 14-bit single-turn absolute encoder according to the driver manual
 - The motor encoder reports motor position, not the anatomical zero of the exoskeleton joint
 - The exoskeleton still needs a defined mechanical reference position for each joint
 - For the standard single-turn encoder case, use manual reference positioning plus Set Origin
 - The manual describes temporary origin and permanent zero; permanent zero is stated for dual encoder models only, so it must not be assumed for the current motors until verified

Recommended first-test procedure
 - Disable motion commands
 - Support the joint mechanically so it cannot fall or rotate unexpectedly
 - Move one joint manually to its defined reference position
 - Measure this position with a digital angle gauge or goniometer
 - Send the CubeMars Set Origin command for that motor
 - Use temporary origin first
 - Read back the encoder position and confirm it is near zero
 - Command only a very small movement, for example +2 degrees
 - Confirm the physical direction is correct
 - Return to zero
 - Command -2 degrees only if mechanically safe
 - Confirm the opposite direction
 - Repeat for hip, knee, and ankle, one motor at a time

Zero persistence check
 - After temporary origin works, power-cycle the system
 - Read the encoder position again at the same mechanical reference
 - If zero is lost, the firmware must repeat the reference procedure after each power-up
 - Do not rely on permanent zero unless the exact motor/driver configuration is confirmed to support it
 - Store software offsets in firmware or configuration only after the mechanical reference is repeatable

6. Angle limits and safe motion envelope
Initial conservative limits
 - Start each joint with approximately +/- 5 degrees around the calibrated zero
 - Increase range only after zero, direction, and feedback are validated
 - Stop before mechanical hard stops
 - Require manual reset after a limit fault

Simulation 06 related limits
 - Supine movement starts with low hip flexion, for example 0 to 10 degrees
 - Knee motion follows the selected constraint only after hip direction is validated
 - Start knee absolute motion below 20 degrees
 - Increase the range gradually only after repeated stable cycles

Simulation 07 related limits
 - Hip remains fixed
 - Knee starts at 0 degrees
 - Start with 10 degrees extension/flexion test range
 - Increase step by step, for example 20, 35, 50, and 75 degrees, only after validation

Firmware behavior
 - Reject target angles outside configured limits
 - Stop if encoder feedback exceeds the allowed range
 - Stop if feedback is missing
 - Stop if current or temperature exceeds the configured threshold
 - Log every limit or safety stop

7. Single motor movement tests
Test sequence for each motor
 - Test hip alone, then knee alone, then ankle alone
 - Keep the other motors disabled or holding a safe fixed position
 - Command a small positive angle and return to zero
 - Command a small negative angle only if mechanically allowed
 - Repeat at low speed first
 - Record target angle, actual angle, current, bus voltage, temperature, and error flags

Expected result
 - Movement direction matches the configured sign
 - Actual position follows target position
 - No mechanical collision occurs
 - Current remains below the selected test limit
 - Motor stops when target is reached

8. Combined movement tests
Simulation 07 knee-only validation
 - Mount or support the leg in the seated configuration
 - Keep the hip fixed
 - Move only the knee through a small trajectory
 - Compare commanded knee angle with encoder feedback
 - Measure current peak and temperature over repeated cycles

Simulation 06 supine validation
 - Mount or support the leg in the lying configuration
 - Test hip trajectory alone first
 - Test knee trajectory alone second
 - Test hip and knee together at low speed
 - Compare the physical motion with the web simulation
 - Add the ankle only after hip and knee are stable

Mannequin-mounted validation
 - Mount the exoskeleton on the mannequin
 - Repeat the same low-angle tests
 - Check for strap movement, frame flex, cable tension, and mechanical binding
 - Increase speed and angle only after stable low-speed operation

9. Electrical measurements during movement
Voltage
 - Measure supply voltage before motion
 - Record minimum supply voltage during acceleration
 - Check voltage drop at motor connectors
 - Check voltage drop across fuse, breaker, and emergency stop

Current
 - Measure idle current
 - Measure current during slow motion
 - Measure current during faster motion
 - Record peak current for each joint and combined movement
 - Stop if current is higher than expected for the load and speed

CAN and timing
 - Record command rate and feedback rate
 - Record missing feedback frames
 - Record CAN error counters
 - Compare commanded target timing with actual motor response

Temperature
 - Measure motor and driver temperature before test
 - Measure temperature after repeated cycles
 - Stop if temperature rises too fast or exceeds the selected safe limit
 - Allow cooldown before continuing

10. Force, load, and pressure measurements
No-load baseline
 - Run every trajectory without external load first
 - Record baseline current, temperature rise, and tracking error

Force gauge test
 - Apply a small resisting force at the shank or foot using a force gauge or spring scale
 - Record force, current increase, and position error
 - Use the same lever arm for repeatable comparison
 - Stop if motion becomes unstable

FSR402 test
 - Record no-load ADC value
 - Record contact threshold
 - Apply light and stronger pressure and confirm monotonic response
 - Compare heel, forefoot, or toe sensor values with visible contact
 - Check for drift during repeated cycles

11. Data logging
Minimum fields
 - Timestamp
 - Test name
 - Joint name and motor ID
 - Target position
 - Actual encoder position
 - Target speed
 - Actual speed if available
 - Current or torque feedback
 - Bus voltage
 - Motor temperature
 - Driver error flags
 - CAN error count
 - FSR raw and filtered values if mounted

Derived values
 - Position error
 - Peak current
 - Overshoot
 - Settling time
 - Cycle time
 - Temperature rise

12. Acceptance criteria and stop conditions
Acceptance criteria
 - No short circuit or unexpected reset
 - Stable controller power and motor supply voltage
 - Stable CAN communication
 - Correct motor direction
 - Correct zero reference after calibration
 - Encoder feedback remains inside software limits
 - No mechanical collision
 - Current and temperature remain within selected test limits
 - FSR sensors respond consistently if used

Immediate stop conditions
 - Emergency stop pressed
 - Unexpected motion direction
 - Mechanical collision or binding
 - Excessive current
 - Excessive temperature
 - CAN feedback lost
 - Encoder value outside safe range
 - Supply voltage drops too much
 - Unusual noise or loose mechanical connection

13. Recommended test progression
Stage 1
 - Power and CAN communication only
 - No motor movement

Stage 2
 - Encoder readback and Set Origin validation
 - One joint at a time

Stage 3
 - Single motor small-angle tests
 - No mannequin

Stage 4
 - Simulation 07 knee-only motion
 - Low speed and low angle

Stage 5
 - Simulation 06 hip and knee motion
 - Low speed and low angle

Stage 6
 - Mannequin-mounted repeated cycles
 - Moderate speed and angle only after previous stages pass

Stage 7
 - Add FSR monitoring
 - Compare pressure/contact data with movement

Stage 8
 - Add ankle movement after hip and knee are validated
